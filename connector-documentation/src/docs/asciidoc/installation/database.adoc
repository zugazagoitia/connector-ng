== Supported databases

The application has been tested against the following database versions (see also the compatibility matrix):

[cols="1,1,2", options="header"]
|===
| Database | Tested version | Initialization script

| MySQL | 8.4.9 | `dbscripts/initial/mysql.sql`
| MariaDB | 12.3.2 | `dbscripts/initial/mariadb.sql`
| PostgreSQL | 17 | `dbscripts/initial/postgres.sql`
| Oracle | 23 | `dbscripts/initial/oracle.sql`
|===

The JDBC drivers for all four databases are bundled with the application; no additional driver installation is required.

== Create a database user with appropriate privileges

Create an empty schema (database) and a dedicated user that owns it.

Because the application relies on distributed (XA) transactions between the database and the JMS broker, the database must support XA and the user must be allowed to recover in-doubt XA transactions:

[cols="1,3", options="header"]
|===
| Database | Requirement

| MySQL / MariaDB
| Grant `XA_RECOVER_ADMIN` to the connector user (MySQL 8+, MariaDB 10.5+), e.g. `+GRANT XA_RECOVER_ADMIN ON *.* TO 'connector'@'%';+`

| PostgreSQL
| Prepared transactions must be enabled on the server: set `max_prepared_transactions` to a value greater than `0` (e.g. `100`) and restart PostgreSQL.

| Oracle
| Grant the privileges required by the transaction manager to recover XA transactions, typically `SELECT` on `SYS.DBA_PENDING_TRANSACTIONS`, `SYS.PENDING_TRANS$` and `SYS.DBA_2PC_PENDING`, and `EXECUTE` on `SYS.DBMS_XA`. Check with your DBA.
|===

NOTE: Some managed database offerings do not expose root/superadmin access and therefore cannot grant the XA recovery privileges (this is the case for some managed MariaDB instances).
The Connector still runs in that situation, but in-doubt transactions cannot be recovered automatically after a crash and may require manual resolution.

== Database initialization

To initialize the connector database, two options are available:

* Run the provided initialization scripts manually (recommended for production)
* Let the application create the schema at startup (development and testing only)

=== Run the initialization scripts

Initialization scripts for each supported database are provided in the distribution package, under:

`dbscripts/initial`

Execute the script matching your database against the empty schema *before* starting the application for the first time, then disable automatic schema management:

[source,properties]
----
spring.jpa.hibernate.ddl-auto=none
----

=== Let the application initialize the database

Set the following property and launch the application:

[source,properties]
----
spring.jpa.hibernate.ddl-auto=update
----

The connector creates the necessary tables on startup.

WARNING: This option is intended for development and testing only, and it is the value used in the sample `application.properties`.
Change it before going to production — `ddl-auto=update` is not a reliable mechanism for managing schema evolution over time.

== Upgrading an existing database

Only initial scripts are provided at the moment; there are no incremental upgrade scripts between releases.
Before upgrading the Connector, compare the initial script of the new release with your current schema (new tables, columns and indexes) and back up the database.
Data migration from a 6.x connector database is not covered by this guide.
