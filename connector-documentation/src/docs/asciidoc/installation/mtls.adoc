[[https-transport-security]]
= HTTPS and Transport Security

The connector listens on plain HTTP and does not terminate TLS itself.
A reverse proxy — Nginx, Apache httpd, Traefik, or equivalent — must be placed in front of it for any deployment beyond a local development setup.

Without HTTPS, all traffic to the connector is exposed to network interception, including login credentials, JWT tokens, REST API requests and uploaded attachments.

NOTE: The SOAP API used for message exchange with backend partners is an exception.
Its messages are encrypted and signed at the application level (WS-Security) by default, so transport-layer encryption is not a strict requirement for that interface — though it is still recommended.

IMPORTANT: Do not expose the connector directly on a network without TLS.
Ensure a reverse proxy with a valid certificate is in place before connecting any backend or gateway partner.

NOTE: Native mTLS support is under development and will be available in a future release.
In the meantime, mTLS can be enforced at the reverse proxy layer independently of the connector.

.Minimal Nginx example (TLS termination and optional client certificate check)
[source,nginx]
----
server {
    listen 443 ssl;
    server_name connector.example.org;

    ssl_certificate         /etc/nginx/tls/connector.crt;
    ssl_certificate_key     /etc/nginx/tls/connector.key;

    # Optional: require a client certificate (mTLS) from backend clients
    # ssl_client_certificate /etc/nginx/tls/backend-ca.crt;
    # ssl_verify_client      on;

    client_max_body_size 210m;   # align with spring.servlet.multipart.max-request-size

    location / {
        proxy_pass         http://127.0.0.1:30000;   # your server.port
        proxy_set_header   Host              $host;
        proxy_set_header   X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto https;
    }
}
----

The values of the example:

* `client_max_body_size 210m` matches the template values `spring.servlet.multipart.max-request-size=210MB` (and `max-file-size=200MB`). Nginx answers `413` for a larger request before it reaches the Connector; the Connector also answers `413` for a request above its own limits. If you change the multipart limits of the Connector, change this value accordingly.
* `proxy_pass http://127.0.0.1:30000` assumes that Nginx runs on the same host as the Connector. When Nginx runs in a container, use the name of the Connector container (or service) and its internal port, for example `+http://connector-ng:30000+`, and put both containers in the same Docker network.
* With `ssl_verify_client on`, a request without a client certificate, or with a certificate that was not issued by the configured CA, is answered by Nginx with `400` and never reaches the Connector. The check applies to every path, including the administration API and Swagger UI.

By default the Connector ignores the `X-Forwarded-*` headers: it does not set `server.forward-headers-strategy`.
Behind the proxy, generated absolute URLs therefore use `http` and the host name without port, for example the server URL in the OpenAPI document (`/v3/api-docs`) and the schema locations in the WSDL (`/services/backend?wsdl`).
To make the Connector use the `X-Forwarded-*` headers (for example `X-Forwarded-Proto`), add `server.forward-headers-strategy=framework` to `application.properties` (with this setting, the OpenAPI server URL became `https://...`).
Only enable it if the Connector can be reached through the proxy alone, because otherwise clients could send these headers themselves.
Note that `proxy_set_header Host $host` drops a non-standard port from the host name; use `$http_host` if the proxy listens on a port other than 443.

See also <<security-guidance>> for the list of endpoints that should not be reachable from untrusted networks.
