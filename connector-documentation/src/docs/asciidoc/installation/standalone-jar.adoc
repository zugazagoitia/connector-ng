[[jar-install]]
= Standalone Deployment — Executable JAR

Use this installation option to run the Connector natively on a host, without a container runtime.

== Prerequisites

In addition to the common <<prerequisites>>, this option requires a Java **21** runtime (JRE) on the host. A full JDK is only needed to build from source.

To check the Java version of the target server:
[source,bash]
----
java -version
----
The output must report version `21.x.x` or higher.

== Steps

=== Step 1 — Obtain the distribution package

The distribution is published as a ZIP archive named `connector-distribution-<version>.zip`.

* **Option A — Download from the e-CODEX Artifactory** (an account is required):
** Release versions: `+https://scm.ecodex.eu/artifactory/libs-release/eu/ecodex/connector/connector-distribution/<version>/+`
** Snapshot versions: `+https://scm.ecodex.eu/artifactory/libs-snapshot/eu/ecodex/connector/connector-distribution/<version>-SNAPSHOT/+`
* **Option B — Build from source.** Requires JDK 21 and internet access to download the dependencies. Docker is additionally required to run the integration tests.
+
[source,bash]
----
./gradlew clean build -x test -x integrationTest
----
+
The distribution is generated in `connector-distribution/build/`:
+
** `connector-distribution-<version>.zip` — the complete package;
** `connector-distribution/standalone/` — the unpacked runnable application.

=== Step 2 — Unpack the distribution

The package has the following layout:

----
connector-distribution/
├── standalone/
│   ├── bin/
│   │   └── connector-ng.jar
│   ├── config/
│   │   ├── application.properties
│   │   ├── log4j2.xml
│   │   ├── banner.txt
│   │   └── keystores/           (test keystores, to be replaced)
│   │       ├── connector-keystore.jks
│   │       ├── connector-truststore.jks
│   │       ├── backend-keystore.jks
│   │       └── backend-truststore.jks
│   ├── lib/                     (JDBC drivers)
│   ├── start.sh
│   └── start.bat
├── dbscripts/
│   └── initial/                 (mysql.sql, mariadb.sql, postgres.sql, oracle.sql)
└── documentation/               (this documentation, HTML and PDF)
----

The `standalone/` directory is the working directory of the application: all relative paths in `application.properties` (`./config/...`, `./data/...`) are resolved from it.
The application creates `./data/` at runtime for the JTA transaction log and the DSS trusted list cache.

=== Step 3 — Configure the application

Edit `standalone/config/application.properties`. The shipped file is a template: its values are placeholders and test values. Replace them by following the checklist in the chapter "Preparing application.properties" of the configuration guide. In particular:

* The template reads several values from environment variables (`DB_URL`, `BROKER_URL`, `S3_ENDPOINT`, `JWT_SECRET_KEY`, ...).
Either export them in the shell or service definition that starts the Connector, or replace the placeholders with literal values.
The complete list is given in the platform chapter of the configuration guide.
* Replace the test keystores with your own key material (see <<certificates-setup>>).
* Create `config/pmode/` and place your P-Mode file there, or remove the `+connector.business-domains.defaults[0].pmode.*+` properties and upload the P-Mode after startup.
If `pmode.file` points to a file that does not exist, the Connector aborts the startup.
* Create the temporary upload directory referenced by `TEMP_DIR_LOCATION`.

.config/application.properties template (all values must be reviewed)
[source,properties]
----
include::{distributiondir}/src/main/resources/config/application.properties[]
----

TIP: For the meaning of every property, see the configuration guide, and apply the <<security-checklist,security checklist>> before going to production.

=== Step 4 — Run the application

On Linux, from the `standalone/` directory:

[source,bash]
----
./start.sh
----

`start.sh` is shipped with execute permission. If the permission was lost while copying the files, restore it with `chmod +x start.sh`.

On Windows, run `start.bat`.

`start.sh` runs `java -Dloader.path=./lib -jar ./bin/connector-ng.jar --spring.config.location=./config/`; `start.bat` runs the same command without `-Dloader.path`.
To pass JVM options (memory, proxy, ...), edit the script or set the `JAVA_TOOL_OPTIONS` environment variable.

TIP: For production, run the Connector as a service (for example a `systemd` unit) under a dedicated, unprivileged user, with `standalone/` as working directory.

=== Step 5 — Verify the runtime status

Once running, the following endpoints are available (replace `30000` with your `server.port` if you changed it):

[cols="2,3", options="header"]
|===
| Endpoint | URL
| Root URL | `http://localhost:30000`
| Health | `http://localhost:30000/actuator/health`
| Application info | `http://localhost:30000/actuator/info`
| Swagger UI | `http://localhost:30000/swagger-ui/index.html`
| SOAP backend API (WSDL) | `http://localhost:30000/services/backend?wsdl`
|===

The health endpoint must report `"status":"UP"`.
