[[docker-install]]
= Standalone Deployment — Containerized (Docker)

== Prerequisites

In addition to the common <<prerequisites>>, this option requires Docker Engine **24 or later** and Docker Compose **2.x or later** on the host.

To verify your installation:
[source,bash]
----
docker --version
docker compose version
----

=== Connector image

The Connector is distributed as a Docker image hosted in the e-CODEX registry (`scm.ecodex.eu`).
You need an account with read access to the registry; log in before pulling:

[source,bash]
----
docker login scm.ecodex.eu
----

[cols="1,3", options="header"]
|===
| Channel | Image

| Release
| `scm.ecodex.eu/docker/connector-ng:<version>` (for example `{project-version}` once released, or `latest`)

| Snapshot (built from the `develop` branch)
| `scm.ecodex.eu/ecodex-docker-snapshots/connector-ng:edge`
|===

Alternatively, build the image from the source repository with `docker build -t connector-ng:local .` (the build runs Gradle inside the container and needs internet access).

=== Image layout

[cols="1,3", options="header"]
|===
| Path in the container | Content

| `/app/bin/connector-ng.jar` | Application
| `/app/config/` | Configuration (`application.properties`, `log4j2.xml`, `banner.txt`, test keystores). Mount your own configuration here.
| `/app/data/` | Runtime data: JTA transaction log (`data/jtalog`) and DSS trusted list cache (`data/tlcache`). Mount a persistent volume here.
| `/app/temp/` | Temporary directory for uploads (`TEMP_DIR_LOCATION`).
|===

The container runs as the unprivileged user `connector` (UID/GID `1000`) and listens on port `30000`.
Mounted directories must be readable (and, for `data` and `temp`, writable) by that user.

== Steps

=== Step 1 — Pull the Connector image

.Release image
[source,bash]
----
docker pull scm.ecodex.eu/docker/connector-ng:latest
----

.Snapshot image
[source,bash]
----
docker pull scm.ecodex.eu/ecodex-docker-snapshots/connector-ng:edge
----

To verify that the image is available locally:
[source,bash]
----
docker images | grep connector-ng
----

=== Step 2 — Configure the environment

Create a file named `connector.env` in your working directory.
It provides the values of the environment variables referenced by the template `application.properties` (see the environment variables table in the platform chapter of the configuration guide).

.connector.env
[source,properties]
----
# Database
DB_USERNAME=connector
DB_PASSWORD=<your_password>
DB_URL=jdbc:mysql://<db-host>:<db-port>/connector
DB_DRIVER_CLASSNAME=com.mysql.cj.jdbc.MysqlXADataSource
DB_DIALECT=org.hibernate.dialect.MySQLDialect

# JWT authentication (at least 32 random bytes, e.g. `openssl rand -base64 32`)
JWT_SECRET_KEY=<jwt_secret_key>
# Overrides connector.admin.password through relaxed binding
CONNECTOR_ADMIN_PASSWORD=<admin_password>

# File storage (S3 / MinIO)
S3_ACCESS_KEY=<access_key>
S3_SECRET_KEY=<secret_key>
S3_REGION=us-east-1
S3_BUCKET=attachments
S3_ENDPOINT=http://<s3-host>:<s3-port>

# Temporary files
TEMP_DIR_LOCATION=/app/temp

# Message broker (ActiveMQ Classic)
BROKER_URL=tcp://<activemq-host>:61616
BROKER_USER=<broker_user>
BROKER_PASSWORD=<broker_password>
----

IMPORTANT: Host names in this file are resolved from *inside* the container.
`localhost` refers to the container itself, not to the Docker host. Use the service name (Docker Compose), the host name or the IP address of the target service.

=== Step 3 — Prepare the configuration directory

Create a local `config/` directory with the following content:

----
config/
├── application.properties
├── log4j2.xml
├── banner.txt
├── keystores/
│   ├── connector-keystore.jks
│   ├── connector-truststore.jks
│   ├── backend-keystore.jks
│   └── backend-truststore.jks
└── pmode/
    └── <your-pmode>.xml
----

* Start from the template files of the distribution package (`config/` folder), or copy them from the image: `docker run --rm --entrypoint cat scm.ecodex.eu/docker/connector-ng:latest /app/config/log4j2.xml > config/log4j2.xml`.
* Replace the test keystores with your own key material (see <<certificates-setup>>). File names are free; they are referenced in `application.properties`.
* Place the P-Mode file exported from your gateway in `config/pmode/`, or remove the `+connector.business-domains.defaults[0].pmode.*+` properties and upload the P-Mode after startup through the administration UI or API.

WARNING: If `pmode.file` points to a file that does not exist, the Connector aborts the startup.

Then edit `config/application.properties`. The file below is the template shipped with the distribution: its values are placeholders and test values (test partner `backend_alice`, sample passwords, `pmode-blue.xml`). Replace them by following the checklist in the chapter "Preparing application.properties" of the configuration guide.

.config/application.properties template (all values must be reviewed)
[source,properties]
----
include::{distributiondir}/src/main/resources/config/application.properties[]
----

TIP: For the meaning of every property, see the configuration guide. Pay particular attention to `spring.jpa.hibernate.ddl-auto` (see <<database-configuration>>) and to the items of the <<security-checklist,security checklist>>.

=== Step 4 — Run the containerized Connector

Run the container, mounting the configuration directory and a persistent data volume:

[source,bash]
----
docker run -d \
  --name connector-ng \
  --env-file connector.env \
  -p 30000:30000 \
  -v "$(pwd)/config:/app/config:ro" \
  -v connector-data:/app/data \
  scm.ecodex.eu/docker/connector-ng:latest
----

To follow the log output:
[source,bash]
----
docker logs -f connector-ng
----

TIP: For a local evaluation environment (Connector, gateway, database, ActiveMQ and MinIO), use the `docker-compose.yml` file at the root of the source repository, as described in its `README.md`.

=== Step 5 — Verify the runtime status

Once running, the following endpoints are available (replace `30000` with your `server.port` if you changed it):

[cols="2,3", options="header"]
|===
| Endpoint | URL
| Root URL | `http://localhost:30000`
| Health | `http://localhost:30000/actuator/health`
| Application info | `http://localhost:30000/actuator/info`
| Swagger UI | `http://localhost:30000/swagger-ui/index.html`
| SOAP backend API (WSDL) | `http://localhost:30000/services/backend?wsdl`
|===

The health endpoint must report `"status":"UP"`.
Log in to the administration API with the admin account configured in `+connector.admin.*+`; you will be asked to change the password at first login.
