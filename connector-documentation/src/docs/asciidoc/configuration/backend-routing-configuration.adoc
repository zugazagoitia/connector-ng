= Routing Rule Configuration

This configuration defines the routing behavior used by the connector to determine to which backend system a message should be transported.

Routing rules allow dynamic selection of backend destinations based on the AS4 properties of the inbound message.

The backend of an inbound message is resolved in this order:

. If the message belongs to a conversation (AS4 `ConversationId`) already associated with a backend, it is delivered to that backend (e.g. replies and evidences).
. Otherwise, if routing is enabled, the rules are evaluated in index order and the first matching rule determines the backend.
. Otherwise, the message is delivered to `default-backend-name`.

NOTE: Routing rules currently apply to the default business domain only.

IMPORTANT: The template routes the test service `Test` to the test partner `backend_alice`. Replace the rules and the default backend with your own services and link partner names.

== Basic configuration
Configuration is provided via `application.properties` under the `+connector.routing.*+` prefix.

.Backend Routing Configuration Properties
[cols="35,40,10,15", options="header"]
|===
| Property | Description | Optional | Example

| `connector.routing.enabled`
| Master switch for message routing logic. When `false`, the rules below are ignored and inbound messages are routed to `default-backend-name`. Connector-to-connector test messages are only intercepted when routing is enabled.
| Yes
| By default, `false` (in connector 6.x the default was `true`)

| `connector.routing.default-backend-name`
| Name of the link partner that receives inbound messages when routing is disabled or no rule matches. If omitted, the Connector uses `default_backend`, which only works if a link partner has that name.
| No (effectively)
| `<backend-courts>`

| `connector.routing.backend-rules[*index*].link-name`
| Name of the target link partner (must match `connector.link.backend[n].link-partners[m].name`). Declare at most one rule per link partner: a second rule with the same `link-name` replaces the first one. Combine conditions with `\|(...)` instead.
| No
| `<backend-registry>`

| `connector.routing.backend-rules[*index*].description`
| Free-text description of the rule.
| Yes
| `<Land registry messages>`

| `connector.routing.backend-rules[*index*].match-clause`
| Expression evaluated against the AS4 properties of the inbound message (see the grammar below). Rules are evaluated in index order; the first matching rule wins.
| No
| `equals(ServiceName, '<service>')`

|===

.Configuration Example
[source,properties]
----
connector.routing.enabled=true
# backend receiving everything that no rule matches
connector.routing.default-backend-name=<backend-courts>
# messages of one service go to another backend
connector.routing.backend-rules[0].link-name=<backend-registry>
connector.routing.backend-rules[0].description=<Land registry messages>
connector.routing.backend-rules[0].match-clause=equals(ServiceName, '<registry-service>')
# several conditions for the same backend are combined in ONE rule ('|' = or, '&' = and)
connector.routing.backend-rules[1].link-name=<backend-insolvency>
connector.routing.backend-rules[1].match-clause=|(equals(ServiceName, '<service-a>'),startswith(Action, '<prefix>'))
----

TIP: Service names, service types and actions are those of your P-Mode. Party identifiers (`FromPartyId`, ...) and `FinalRecipient` can also be used.

.Match clause grammar
[source]
----
<ROUTING_RULE_PATTERN> ::= <BOOLEAN_EXPRESSION> | <COMPARE_EXPRESSION> | <NOT_EXPRESSION>
<BOOLEAN_EXPRESSION> ::= <OPERAND>(<ROUTING_RULE_PATTERN>, <ROUTING_RULE_PATTERN>)
<COMPARE_EXPRESSION> ::= equals(<AS4_TYPE>, '<VALUE>') | startswith(<AS4_TYPE>, '<VALUE>')
<NOT_EXPRESSION> ::= not(<ROUTING_RULE_PATTERN>)
<OPERAND> ::= "&" | "|"
<AS4_TYPE> ::= ServiceType | ServiceName | FinalRecipient | Action | FromPartyId | FromPartyRole
| FromPartyIdType
<VALUE> ::= <VALUE><LETTER> | <LETTER>
----

`<VALUE>` may contain letters `[a-zA-Z]` and digits `[0-9]`. Other printable characters are untested, and the characters `'`, `\`, `|`, `&`, `(` and `)` are not supported.
Comparisons are case-sensitive.
