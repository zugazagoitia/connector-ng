= Business Document Configuration

This configuration defines the settings used for business document validation: signature verification, trust validation, and authentication provider configuration.
The result of the validation is recorded in the trust-ok token attached to outgoing messages.

== Basic configuration
Configuration is provided via `application.properties` under the `+connector.business-document.*+` prefix.

.Business Document Configuration Properties
[cols="35,40,10,15", options="header"]
|===
| Property | Description | Optional | Example

| `connector.business-document.service-provider`
| Name of the organisation operating this Connector, recorded in the trust-ok token. The template value `TestProvider` must be replaced.
| No
| `<Ministry of Justice of ...>`

| `connector.business-document.country`
| Two-letter ISO 3166-1 country code of this Connector, recorded in the trust-ok token. The template value `BL` is the "blue" test country and must be replaced.
| No
| `<XX>`

| `connector.business-document.default-advanced-system-type`
| Default type of advanced electronic system (AES) used to qualify the document when the backend does not specify it: `SIGNATURE_BASED` (the document is electronically signed) or `AUTHENTICATION_BASED` (the author was authenticated by an identity provider).
| No
| `SIGNATURE_BASED`

| `connector.business-document.allowed-advanced-system-types`
| Comma-separated list of the AES types accepted from backends.
| Yes
| By default, all types: `SIGNATURE_BASED,AUTHENTICATION_BASED`

| `connector.business-document.signature.validation.truststore.path`
| Truststore containing the certificates/CA chains used to validate the signatures of the business documents submitted by *your* backends (distinct from the signing keystore used in the container configuration). The template points to the sample `connector-truststore.jks`.
| No
| `file:./config/keystores/<national-signers-truststore>.p12`

| `connector.business-document.signature.validation.truststore.password`
| Password protecting the truststore.
| No
| `*secret*`

| `connector.business-document.signature.validation.truststore.type`
| Truststore format: `JKS` or `PKCS12`.
| Yes
| By default, set to `JKS`

| `connector.business-document.signature.validation.constraints-xml`
| DSS validation policy (ETSI TS 102 853 / TS 119 102 constraint file) that constrains which signature/digest algorithms and certificate qualities are accepted when validating business document signatures.
| Yes
| By default, set to `classpath:/102853/constraint.xml`

| `connector.business-document.signature.validation.truststore-enabled`
| Whether the truststore above is used as a trust anchor.
| Yes
| By default, set to `true`

| `connector.business-document.signature.validation.trusted-list-source`
| Name of a trusted list source declared under `connector.dss.trust-list-sources.<name>` (see <<dss-trust-list-sources>>). When set, certificates are also trusted if they chain to a service listed in that trusted list.
| Yes
| `eu`

| `connector.business-document.signature.validation.ignore-store-enabled`
| Whether the certificates of the ignore store below are excluded from the validation.
| Yes
| By default, set to `false`

| `connector.business-document.signature.validation.ignore-store.path` / `.password` / `.type`
| Keystore holding certificates to ignore during validation.
| Yes
| `file:./config/keystores/ignore-store.jks`


| `connector.business-document.authentication-validation.identity-provider`
| Name of the identity provider recorded in the token for `AUTHENTICATION_BASED` documents. The template value `ERV` comes from the Austrian test set-up; use the identity provider of your use case.
| Required when `AUTHENTICATION_BASED` is used
| `<identity provider>`

|===

.Configuration Example
[source,properties]
----
connector.business-document.service-provider=<Ministry of Justice of ...>
connector.business-document.country=<XX>
connector.business-document.default-advanced-system-type=SIGNATURE_BASED
connector.business-document.signature.validation.truststore.path=file:./config/keystores/<national-signers-truststore>.p12
connector.business-document.signature.validation.truststore.password=${SIGNERS_TRUSTSTORE_PASSWORD}
connector.business-document.signature.validation.truststore.type=PKCS12
connector.business-document.signature.validation.constraints-xml=classpath:/102853/constraint.xml
connector.business-document.authentication-validation.identity-provider=<identity provider>
# Optional: also trust certificates listed in the EU trusted lists (see the DSS configuration)
#connector.business-document.signature.validation.trusted-list-source=eu
----

NOTE: OCSP, CRL and AIA checks are always enabled during certificate validation; the connector therefore needs outbound access (directly or through the DSS proxy) to the revocation services of the signers' CAs.
