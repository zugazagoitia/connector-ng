= REM Evidence Configuration

The connector generates ETSI-REM evidence for message lifecycle events.
Generated evidences are electronically signed (XAdES) and include mandatory issuer metadata.

Configuration is provided via `application.properties` under the `+connector.evidences.*+` prefix.

== Signature configuration

Properties under `+connector.evidences.signature.*+` control how REM evidence XML is signed.

.ETSI-REM Evidences Signature Configuration Properties
[cols="35,40,10,15", options="header"]
|===
| Property | Description | Optional | Example

| `connector.evidences.signature.keystore.path`
| Classpath or filesystem path to the keystore holding the signing private key.
| No
| `file:./config/keystores/<connector-signing-keystore>.p12`

| `connector.evidences.signature.keystore.password`
| Password for the keystore.
| No
| *(secret)*

| `connector.evidences.signature.keystore.type`
| Keystore type (for example `JKS` or `PKCS12`).
| Yes
| By default, set to `JKS`

| `connector.evidences.signature.private-key.alias`
| Alias of the private key within the keystore. The corresponding public key must be shared with communication partners.
| No
| `<signing-key-alias>`

| `connector.evidences.signature.private-key.password`
| Password to unlock the private key entry.
| No
| *(secret)*

|===

NOTE: The digest algorithm (SHA-256) and the signature algorithm (RSA) used for evidences are fixed in the current version.
The `connector.evidences.signature.digest-algorithm` and `connector.evidences.signature.payload-digest-algorithm` properties found in earlier samples are not bound and have no effect.

.Configuration Example
[source,properties]
----
connector.evidences.signature.keystore.path=file:./config/keystores/<connector-signing-keystore>.p12
connector.evidences.signature.keystore.password=${SIGNING_KEYSTORE_PASSWORD}
connector.evidences.signature.keystore.type=PKCS12
connector.evidences.signature.private-key.alias=<signing-key-alias>
connector.evidences.signature.private-key.password=${SIGNING_KEY_PASSWORD}
----

== Issuer configuration

Properties under `+connector.evidences.issuer.*+` are embedded into every generated REM evidence and identify your organisation as the evidence issuer.

IMPORTANT: The template values (`Unknown Street 1`, `Connector NG`, `mailto:gateway@connector.example`, ...) are placeholders. Set the legal address of your organisation, and the party name and endpoint address of *your* gateway exactly as declared in your P-Mode.
In connector 6.x, the AS4 party information was taken from the uploaded P-Mode; in 7.x it must be configured here.

.Issuer Configuration Properties
[cols="35,40,10,15", options="header"]
|===
| Property | Description | Optional | Example

| `connector.evidences.issuer.postal-address.street`
| Issuer street address (mandatory for evidence building).
| No
| `<street and number>`

| `connector.evidences.issuer.postal-address.locality`
| Issuer locality.
| No
| `<city>`

| `connector.evidences.issuer.postal-address.zip-code`
| Issuer postal code.
| No
| `<postal code>`

| `connector.evidences.issuer.postal-address.country`
| Issuer country (two-letter ISO 3166-1 code recommended).
| No
| `<XX>`

| `connector.evidences.issuer.as4-party.name`
| AS4 party name of the gateway through which evidences are sent (home party in PMode configuration).
| No
| `<gateway party id>`

| `connector.evidences.issuer.as4-party.endpoint-address`
| AS4 endpoint address of the evidence issuer gateway.
| No
| `<gateway endpoint>`

|===

.Configuration Example
[source,properties]
----
connector.evidences.issuer.as4-party.name=<gateway party id from the P-Mode>
connector.evidences.issuer.as4-party.endpoint-address=<gateway endpoint from the P-Mode>

connector.evidences.issuer.postal-address.street=<street and number>
connector.evidences.issuer.postal-address.locality=<city>
connector.evidences.issuer.postal-address.zip-code=<postal code>
connector.evidences.issuer.postal-address.country=<XX>
----

== Message processing options

.Evidence Message Processing Configuration
[cols="35,40,10,15"]
|===
| Property | Description | Optional | Default

| `connector.message-processing.send-generated-evidences-to-backend`
| When `true`, generated evidences are also forwarded to the backend after submission to the gateway.
| Yes
| `true`

| `connector.message-processing.auto-trigger-delivery-evidences`
| When `true`, a `DELIVERY` evidence is generated automatically once the message has been delivered to the backend.
| Yes
| `false` (the template sets `true`)

|===

See also the message processing and connector queue configuration chapters.
