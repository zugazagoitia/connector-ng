= Connector-to-Connector (C2C) Test

The C2C test feature allows two connector instances to verify end-to-end AS4 connectivity without involving a real backend on either side.
It has two parts:

Receiving test messages::
Whenever `connector.routing.enabled=true`, the Connector adds a built-in routing rule (with high priority) that sends an inbound message to the internal backend `default_test_backend` when its service name *and* service type match `connector.c2ctests.service.*`, *or* its action matches `connector.c2ctests.action` (rule `|(&(equals(ServiceName, ...), equals(ServiceType, ...)), equals(Action, ...))`).
Such a message is not forwarded to any real backend: the Connector marks it as delivered and, when `connector.message-processing.auto-trigger-delivery-evidences=true`, answers with a `DELIVERY` evidence (the `RELAY_REMMD_ACCEPTANCE` evidence is generated for every inbound message).
The interception is switched off when routing is disabled; with routing disabled, test messages go to the default backend like any other message.

Sending test messages::
`POST /api/v1/admin/messages/outbound/test` (administration API, JWT required, not shown in Swagger UI) sends a test message with the configured service and action to the partner gateway. `connector.c2ctests.enabled=false` blocks only this endpoint: it then answers `409` with `C2C Test message is disabled`.

[IMPORTANT]
====
* The C2C test mode is *enabled by default*. Make sure that no production service or action uses the test values, in particular the action `ConTest_Form`: a business message with this action is treated as a test message even if its service is a production service.
* The service and action must be declared in the P-Mode of both connectors and gateways.
====

== Sending a test message

The endpoint takes a `multipart/form-data` request with the same parts as `POST /api/v1/messages/outbound` (see the backend API description in the architecture guide), without `as4Properties.service.*` and `as4Properties.action.*`, which come from the configuration:

[source,bash]
----
curl -X POST https://<connector-host>/api/v1/admin/messages/outbound/test \
  -H "Authorization: Bearer ${TOKEN}" \
  -F "businessDomainIdentifier=default_business_domain" \
  -F "backendMessageIdentifier=<unique id>" \
  -F "businessContent.xmlContent=@content.xml;type=application/xml" \
  -F "businessContent.businessDocument.document=@document.pdf;type=application/pdf" \
  -F "businessContent.businessDocument.aesType=SIGNATURE_BASED" \
  -F "as4Properties.conversationIdentifier=<conversation id>" \
  -F "as4Properties.originalSender=<sender>" \
  -F "as4Properties.finalRecipient=<recipient>" \
  -F "as4Properties.fromParty.identifier=<your party id>" \
  -F "as4Properties.fromParty.identifierType=<party id type>" \
  -F "as4Properties.fromParty.role=<role>" \
  -F "as4Properties.toParty.identifier=<partner party id>" \
  -F "as4Properties.toParty.identifierType=<party id type>" \
  -F "as4Properties.toParty.role=<role>"
----

== Basic configuration
Configuration is provided via `application.properties` under the `+connector.c2ctests.*+` prefix.
All properties are optional: when a property is not set, its default value is used.

.Connector-to-Connector (C2C) Test Configuration
[cols="35,40,10,15", options="header"]
|===
| Property | Description | Optional | Example

| `connector.c2ctests.enabled`
| Allows sending test messages with `POST /api/v1/admin/messages/outbound/test`. It does not affect the interception of inbound test messages, which happens whenever `connector.routing.enabled=true`.
| Yes
| By default, set to `true`

| `connector.c2ctests.action`
| The AS4 action value that identifies a message as a C2C test message. Must match the action defined in the P-Mode used for test traffic. Must not be blank.
| Yes
| By default, set to `ConTest_Form`

| `connector.c2ctests.service.name`
| The AS4 service name used to identify C2C test messages (together with the service type; the action alone is also enough, see above). Must match the service name in the P-Mode. Must not be blank.
| Yes
| By default, set to `Connector-TEST`

| `connector.c2ctests.service.type`
| The AS4 service type URI qualifying `connector.c2ctests.service.name`. Must not be blank.
| Yes
| By default, set to `urn:e-codex:services:`

|===

NOTE: The configuration is validated at startup. An empty value (for example
`connector.c2ctests.action=`) counts as set to blank and stops the connector.
Remove or comment out the line to use the default.

.Configuration Example
[source,properties]
----
connector.c2ctests.enabled=true
connector.c2ctests.action=ConTest_Form
connector.c2ctests.service.name=Connector-TEST
connector.c2ctests.service.type=urn:e-codex:services:
----

== Migration from 6.x

In 6.x these properties used the prefix `c2ctests.*`. In 7.x they are renamed as follows:

[cols="50,50"]
|===
| 6.x property | 7.x property

| `c2ctests.enabled`
| `connector.c2ctests.enabled`

| `c2ctests.action` (bound to `c2ctests.action.action`)
| `connector.c2ctests.action`

| `c2ctests.service.name`
| `connector.c2ctests.service.name`

| `c2ctests.service.serviceType`
| `connector.c2ctests.service.type`
|===

Use the 7.x property names in `application.properties`.
