= Container Configuration

This configuration defines the cryptographic settings used by the connector security library for:

* Token generation (PDF and XML)
* ASiC-S container signing
* ASiC-S container validation (inbound messages)

IMPORTANT: The template refers to the sample keystore `connector-keystore.jks` (password `12345`, alias `connector_blue`). Use your own signing key, usually the same key as for REM evidences. Its certificate must be distributed to your partner connectors (through their P-Mode truststore).

== Basic configuration
Configuration is provided via `application.properties` under the `+connector.container.*+` prefix.

NOTE: The configuration is validated at startup. A missing or blank mandatory value stops the connector with an error naming the offending property.

.Container Configuration Properties
[cols="35,40,10,15", options="header"]
|===
| Property | Description | Optional | Example

| `connector.container.signature.keystore.path`
| Path to the keystore holding the private key/certificate used to sign containers and tokens. Use the `file:` or `classpath:` prefix.
| No
| `file:./config/keystores/<connector-signing-keystore>.p12`

| `connector.container.signature.keystore.password`
| Password protecting the keystore file itself.
| No
| `${CONTAINER_KEYSTORE_PASSWORD}`

| `connector.container.signature.keystore.type`
| Keystore format: `JKS` (legacy Java format) or `PKCS12`.
| Yes
| By default, set to `JKS`

| `connector.container.signature.private-key.alias`
| Alias identifying which key entry inside the keystore to use for signing
| No
| `<signing-key-alias>`

| `connector.container.signature.private-key.password`
| Password protecting that specific private key entry
| No
| `${CONTAINER_KEY_PASSWORD}`

| `connector.container.signature.digest-algorithm`
| Digest algorithm used when signing.
| Yes
| By default, set to `SHA256`

| `connector.container.signature.encryption-algorithm`
| Encryption algorithm of the signing key.
| Yes
| By default, set to `RSA`

| `connector.container.signature.validation.constraints-xml`
| ETSI TS 119 102 / DSS validation policy used when validating inbound ASiC-S containers.
| Yes
| By default, set to `classpath:/102853/constraint.xml`

| `connector.container.signature.validation.ocsp-enabled`
| Whether OCSP is queried when verifying certificates.
| Yes
| By default, set to `true`

| `connector.container.signature.validation.crl-enabled`
| Whether CRLs are queried when verifying certificates.
| Yes
| By default, set to `true`

| `connector.container.signature.validation.aia-enabled`
| Whether the Authority Information Access extension is used to find issuer certificates.
| Yes
| By default, set to `true`

| `connector.container.signature.validation.trusted-list-source`
| Name of a trusted list source declared under `connector.dss.trust-list-sources.<name>` (see <<dss-trust-list-sources>>). When set, certificates are also trusted if they chain to a service listed in that trusted list. The name must be declared.
| Yes
| `eu`

| `connector.container.signature.validation.ignore-store-enabled`
| Whether the certificates of the ignore store below are excluded from the validation. When `true`, the `ignore-store.*` block must be configured, otherwise the startup stops (`ignore-store must be configured when ignore-store-enabled is true`).
| Yes
| By default, set to `false`

| `connector.container.signature.validation.ignore-store.path` / `.password` / `.type`
| Keystore holding certificates to ignore during validation.
| Yes
| `file:./config/keystores/ignore-store.jks`

|===

IMPORTANT: Inbound containers are validated against the *truststore of the P-Mode* of the business domain (`connector.business-domains.defaults[n].pmode.truststore`, or the truststore uploaded with the P-Mode), not against a truststore configured in this chapter.
That truststore must contain the container signing certificates of your partner connectors.

NOTE: OCSP, CRL and AIA checks are enabled by default and can be switched off with `ocsp-enabled`, `crl-enabled` and `aia-enabled` under `connector.container.signature.validation.*`. The connector then needs outbound access (directly or through the DSS proxy) to the revocation services of the signers' CAs.

.Configuration Example
[source,properties]
----
connector.container.signature.keystore.path=file:./config/keystores/<connector-signing-keystore>.p12
connector.container.signature.keystore.password=${SIGNING_KEYSTORE_PASSWORD}
connector.container.signature.keystore.type=PKCS12
connector.container.signature.private-key.alias=<signing-key-alias>
connector.container.signature.private-key.password=${SIGNING_KEY_PASSWORD}
connector.container.signature.validation.constraints-xml=classpath:/102853/constraint.xml
connector.container.signature.digest-algorithm=SHA256
----
