= DSS Tools configuration

The connector uses the link:https://github.com/esig/dss[DSS (Digital Signature Service) library] of the European Commission to validate signatures and certificates.
This chapter describes how DSS is configured: the trusted list cache, the outbound proxy and the trusted list sources.

NOTE: The configuration is validated at startup. A blank mandatory value (for example an empty `tl-url`), an invalid cron expression or a non-positive cache expiration stops the connector with an error naming the offending property.

== Trusted list configurations

The connector supports the use of trusted lists as a trust source for certificate validation. Trusted lists can be configured **only** via the (spring environment) property file.

=== Basic configuration
==== Cache configuration
The basic DSS configuration includes the location of the trusted list cache. This cache is a local filesystem cache where DSS stores the downloaded Trusted List (TL) and List of Trusted Lists (LOTL) files. The cache is used as a fallback when the download fails (the cached files are then used while they are younger than `expiration`).

Configuration is provided via `application.properties` under the `+connector.dss.cache.*+` prefix.

.DSS Cache Configuration Properties
[cols="35,40,10,15", options="header"]
|===
| Property | Description | Optional | Example

| `connector.dss.cache.location`
| Local filesystem directory where DSS stores the downloaded Trusted List (TL) and List of Trusted Lists (LOTL) files. It is created at startup if it does not exist and must be writable. Use a resource location with the `file:` prefix.
| Recommended
| `file:./data/tlcache`. By default, `<java.io.tmpdir>/dss-cache`

| `connector.dss.cache.expiration`
| Max age of the cached files that are still used when the online download fails.
Format: Spring Boot duration shorthand (e.g., "1d", "12h", "30m"). Must be positive.
| Yes
| By default, set to `1d`

| `connector.dss.cache.refresh-cron`
| Schedule for refreshing the trusted lists, as a Spring cron expression with 6 fields (seconds first).
| Yes
| `0 0 */6 * * *`. By default, set to *every 6 hours*
|===

.Configuration Example
[source,properties]
----
# cache configuration
connector.dss.cache.location=file:./data/tlcache
connector.dss.cache.expiration=1d
connector.dss.cache.refresh-cron=0 0 */6 * * *
----

==== Proxy configuration
A proxy can be configured for every outbound connection made by DSS. This proxy is used to

* download CRLs (certificate revocation lists)
* query OCSP responders
* download trusted lists

Configuration is provided via `application.properties` under the `+connector.dss.proxy.*+` prefix.
The proxy is optional. If you configure a proxy, set both its host and its port.

If no `+connector.dss.proxy.*+` property is set, the Connector falls back, for each scheme, to the JVM system properties `https.proxyHost`/`https.proxyPort` (`http.proxyHost`/`http.proxyPort`) and then to the environment variables `HTTPS_PROXY` (`HTTP_PROXY`), in the form `http://host:port`. As soon as one `+connector.dss.proxy.*+` property is set, these fallbacks are not used for either scheme. The startup log shows the source used (`setting DSS https proxy configuration from ...` or `No DSS https proxy configuration found`).

.DSS Proxy Configuration Properties
[cols="35,40,10,15", options="header"]
|===
| Property | Description | Optional | Example

| `connector.dss.proxy.http.host`
| Hostname of the HTTP proxy server.
| Yes
| `proxy1.example.com`

| `connector.dss.proxy.http.port`
| Port of the HTTP proxy server.
| Yes
| `8080`

| `connector.dss.proxy.https.host`
| Hostname of the HTTPS proxy server.
| Yes
| `proxy1.example.com`

| `connector.dss.proxy.https.port`
| Port of the HTTPS proxy server.
| Yes
| `8080`
|===

NOTE: `connector.dss.proxy.http` and `connector.dss.proxy.https` are bound to the DSS `ProxyProperties` class, so its other fields `user`, `password`, `scheme` and `excluded-hosts` (comma-separated) can be set in the same way, e.g. `connector.dss.proxy.https.user`. They are accepted at startup; their effect on a real proxy was not tested.

.Configuration Example
[source,properties]
----
# proxy configuration
# this proxy is used for downloading trusted lists, CRL updates and OCSP requests
connector.dss.proxy.http.host=proxy1.example.com
connector.dss.proxy.http.port=8080
connector.dss.proxy.https.host=proxy1.example.com
connector.dss.proxy.https.port=8080
----

[[dss-trust-list-sources]]
=== Trusted list sources (EU-LOTL and national TLs)

Trusted list sources are declared as named groups: in `connector.dss.trust-list-sources.<name>.lotl-sources[<index>]`, `<name>` (for example `eu`) is the name of the trust source.
A trust source can contain several Lists of Trusted Lists (LOTL) and several trusted lists (TL).
The name of the trust source is referenced by the `trusted-list-source` property of the business document and container signature validation (see the business document configuration chapter).

Configuration is provided via `application.properties` under the `+connector.dss.trust-list-sources.*+` prefix.

.DSS EU-LOTL Configuration Properties
[cols="35,40,10,15", options="header"]
|===
| Property | Description | Optional | Example

| `connector.dss.trust-list-sources.<name>.lotl-sources[<index>].lotl-url`
| LOTL source: the EU master list that points to each member state's national Trusted List.
Must not be blank.
| Yes
| `https://ec.europa.eu/tools/lotl/eu-lotl.xml`. By default, set to the *EU LOTL*.

| `connector.dss.trust-list-sources.<name>.lotl-sources[<index>].signing-certificates-announcement-uri`
| URL of the Official Journal notice announcing the certificates used to verify the LOTL's own signature (the trust anchor for the LOTL).
Must not be blank.
| Yes
| `https://eur-lex.europa.eu/legal-content/EN/TXT/?uri=uriserv:OJ.C_.2019.276.01.0001.01.ENG`. By default, set to the *EU Official Journal notice*.

| `connector.dss.trust-list-sources.<name>.lotl-sources[<index>].pivot-support`
| Enables pivot support, so DSS can follow historical LOTL "pivot" versions and keep trust anchors valid as the EU rotates LOTL signing certificates over time.
| Yes
| By default, set to `true`

| `connector.dss.trust-list-sources.<name>.lotl-sources[<index>].signing-certs.path` / `.password` / `.type`
| Keystore holding the certificates allowed to sign the LOTL. Without it DSS logs `Certificate source is not defined for the LOTL` and cannot validate the LOTL signature. When the block is present, `path` and `password` are required.
| Yes
| `file:./config/keystores/lotl-signers.jks`

| `connector.dss.trust-list-sources.<name>.tl-sources[<index>].tl-url`
| Direct Trusted List (TL) source, for a national trusted list that is not reached through a LOTL.
Required for every `tl-sources` entry, and must not be blank.
| No (per entry)
| `https://www.signatur.rtr.at/vertrauensliste.xml`

| `connector.dss.trust-list-sources.<name>.tl-sources[<index>].signing-certs.*`
| Optional keystore (`path`, `password`, `type`) holding the certificates used to verify the signature of the TL. When the block is present, `path` and `password` are required.
| Yes
| `file:./config/keystores/tl-signing.jks`
|===

.Configuration Example
[source,properties]
----
connector.dss.trust-list-sources.eu.lotl-sources[0].lotl-url=https://ec.europa.eu/tools/lotl/eu-lotl.xml
connector.dss.trust-list-sources.eu.lotl-sources[0].signing-certificates-announcement-uri=https://eur-lex.europa.eu/legal-content/EN/TXT/?uri=uriserv:OJ.C_.2019.276.01.0001.01.ENG
connector.dss.trust-list-sources.eu.lotl-sources[0].pivot-support=true
connector.dss.trust-list-sources.eu.tl-sources[0].tl-url=https://www.signatur.rtr.at/vertrauensliste.xml
----

To pick up trusted list changes, restart the connector at least once within the cache expiration period.

=== Time-stamp servers
Configuration is provided via `application.properties` under the `+connector.dss.time-stamp-servers.*+` prefix.

.DSS Time Stamp Servers Configuration Properties
[cols="35,40,10,15", options="header"]
|===
| Property | Description | Optional | Example

| `connector.dss.time-stamp-servers.*key*.url`
| URL of the RFC 3161 Time-Stamping Authority (TSA). The `dss.nowina.lu/pki-factory` URLs of the examples and of the template are public *test* TSAs of the DSS project; never use them in production. Required for every configured server.
| Yes
| `http://dss.nowina.lu/pki-factory/tsa/good-tsa`

| `connector.dss.time-stamp-servers.*key*.policy-oid`
| Optional TSA policy OID to request.
| Yes
| `1.2.3.4`

|===

.Configuration Example
[source,properties]
----
connector.dss.time-stamp-servers.t1.url=http://dss.nowina.lu/pki-factory/tsa/good-tsa
connector.dss.time-stamp-servers.ee-good-tsa.url=http://dss.nowina.lu/pki-factory/tsa/ee-good-tsa
----

NOTE: Currently, timestamping is not used by the connector.

== Full configuration example

.Full Configuration Example
[source,properties]
----
# Cache configuration
connector.dss.cache.location=file:./data/tlcache
connector.dss.cache.expiration=1d
connector.dss.cache.refresh-cron=0 0 */6 * * *

# Proxy configuration
connector.dss.proxy.http.host=proxy1.example.com
connector.dss.proxy.http.port=8080
connector.dss.proxy.https.host=proxy1.example.com
connector.dss.proxy.https.port=8080

# LOTL source
connector.dss.trust-list-sources.eu.lotl-sources[0].lotl-url=https://ec.europa.eu/tools/lotl/eu-lotl.xml
connector.dss.trust-list-sources.eu.lotl-sources[0].signing-certificates-announcement-uri=https://eur-lex.europa.eu/legal-content/EN/TXT/?uri=uriserv:OJ.C_.2019.276.01.0001.01.ENG
connector.dss.trust-list-sources.eu.lotl-sources[0].pivot-support=true
connector.dss.trust-list-sources.eu.tl-sources[0].tl-url=https://www.signatur.rtr.at/vertrauensliste.xml

# Timestamp (TSA) servers
connector.dss.time-stamp-servers.t1.url=http://dss.nowina.lu/pki-factory/tsa/good-tsa
----
