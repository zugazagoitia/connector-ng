[[user-authentication]]
= Admin User Authentication Configuration

The REST API and the administration portal are secured with JWT bearer tokens.
These properties configure the JWT token lifecycle and the built-in admin account that is created at startup.

* Obtain a token pair with `POST /api/v1/auth/login` (`{"username": "...", "password": "..."}`); the response contains `accessToken`, `refreshToken`, `expiresIn`, `refreshExpiresIn` and `mustChangePassword`.
* Send the access token in the `Authorization: Bearer <token>` header.
* Renew it with `POST /api/v1/auth/refresh`, and end the session with `POST /api/v1/auth/logout`.
* At first login, `mustChangePassword` is `true`: change the password with `POST /api/v1/auth/change-password` before using the rest of the API.
* Additional users and roles are managed through `/api/v1/admin/users` (requires the `ADMIN` role).

IMPORTANT: Change `connector.admin.password` and `connector.auth.security.jwt.secret`
before deploying to any non-development environment.
The values of the sample configuration (`admin` / `123456`) are insecure placeholders.

.Admin Authentication Properties
[cols="35,40,10,15", options="header"]
|===
| Property | Description | Optional | Example

| `connector.auth.security.jwt.secret`
| Secret used to sign (HMAC-SHA) the JWT access tokens. The string is used as-is (its UTF-8 bytes, not Base64-decoded) and must be at least 32 bytes long. Never commit it to version control.
| No
| `${JWT_SECRET_KEY}` — generate a value with `openssl rand -base64 32`

| `connector.auth.security.jwt.expiration`
| How long an access token remains valid before it must be refreshed.
| Yes
| By default, set to `60m` (the sample configuration uses `15m`)

| `connector.auth.security.jwt.issuer`
| Issuer claim embedded in the JWT.
| Yes
| By default, set to `connector.ecodex.eu`

| `connector.auth.security.jwt.refresh-token.expiration`
| How long a refresh token remains valid, allowing a client to renew its access token without logging in again.
| No
| `30d`

| `connector.auth.security.jwt.refresh-token.cleanup-cron`
| Spring cron expression (six fields, starting with seconds) controlling when expired refresh tokens are purged from the database.
| No
| `+0 0 3 * * *+` (daily at 03:00)

| `connector.admin.username`
| Username of the built-in admin account, created at startup if it does not exist.
| No
| `admin`

| `connector.admin.password`
| Initial password of the built-in admin account. The user must change it at first login.
| No
| `${ADMIN_PASSWORD}`

| `connector.admin.enabled`
| Set to `false` to disable the built-in admin account.
| Yes
| By default, set to `true`

| `connector.admin.email`
| Email address associated with the built-in admin account.
| No
| `admin@example.com`
|===

NOTE: Expired refresh tokens accumulate in the database until the cleanup job removes them.

.Configuration example
[source,properties]
----
# JWT session management
connector.auth.security.jwt.secret=${JWT_SECRET_KEY}
connector.auth.security.jwt.expiration=15m
connector.auth.security.jwt.issuer=connector.ecodex.eu
connector.auth.security.jwt.refresh-token.expiration=30d
connector.auth.security.jwt.refresh-token.cleanup-cron=0 0 3 * * *

# Built-in admin account
connector.admin.username=admin
connector.admin.password=${ADMIN_PASSWORD}
connector.admin.enabled=true
connector.admin.email=admin@example.com
----
