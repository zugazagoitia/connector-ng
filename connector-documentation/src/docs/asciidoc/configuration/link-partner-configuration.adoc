[[link-partner-configuration]]
= Backend Link Partner Configuration

This configuration declares the backend applications (also called connector clients) allowed to exchange messages with the Connector over the SOAP backend API, and the WS-Security key material used to protect that exchange.

A *link* bundles the shared transport and security configuration of the SOAP endpoint; the *link partners* declared under it are the individual backend applications using that endpoint, each with its own name, certificate and delivery mode.

NOTE: Only SOAP backend links are supported in this version. Gateway links are no longer configured here: the gateway is reached through the shared JMS broker (see the gateway queue configuration chapter).

IMPORTANT: The template declares one test partner (`backend_alice`, certificate `cn=alice`, push address `http://localhost:port/...`) and refers to the sample backend keystores. Replace the whole block with your own partners and key material.

== Key material

The SOAP messages between the backend applications and the Connector are signed and encrypted (WS-Security, policy `classpath:/policy/backend.policy.xml`).
This requires:

* one key pair for the Connector (in the *backend keystore*); its certificate is given to every backend application;
* one key pair per backend application (kept by the backend); its certificate is imported into the Connector *backend truststore*.

The Connector identifies the calling backend by the subject DN of the certificate that signed the request, and encrypts the messages for a backend with the certificate stored under that partner's `encryption-alias`.

See the certificates chapter of the installation guide for step-by-step key generation and exchange.

== Properties

Configuration is provided via `application.properties` under the `+connector.link.backend[n].*+` prefix.
Several links can be declared by incrementing the index `n`, and several partners per link with `link-partners[m]`.

.Link configuration properties
[cols="35,40,10,15", options="header"]
|===
| Property | Description | Optional | Example

| `connector.link.backend[n].link-config.name`
| Free label of the link, used in logs and the administration portal.
| No
| `<national-backends>`

| `connector.link.backend[n].link-config.properties.endpoint.keystore.path`
| Keystore holding the Connector's private key for this link (signing responses, decrypting requests).
| No
| `file:./config/keystores/<backend-keystore>.p12`

| `connector.link.backend[n].link-config.properties.endpoint.keystore.password`
| Password of that keystore.
| No
| `${BACKEND_KEYSTORE_PASSWORD}`

| `connector.link.backend[n].link-config.properties.endpoint.keystore.type`
| Keystore format: `JKS` or `PKCS12`.
| Yes
| By default, `JKS`

| `connector.link.backend[n].link-config.properties.endpoint.private-key.alias`
| Alias of the Connector key entry in the keystore. Its certificate is the one you give to the backend applications. List the aliases with `keytool -list -keystore <file>`.
| No
| `<connector-backend-key>`

| `connector.link.backend[n].link-config.properties.endpoint.private-key.password`
| Password of that key entry.
| No
| `${BACKEND_KEY_PASSWORD}`

| `connector.link.backend[n].link-config.properties.endpoint.truststore.path`
| Truststore holding the certificates of all backend applications of this link.
| No
| `file:./config/keystores/<backend-truststore>.p12`

| `connector.link.backend[n].link-config.properties.endpoint.truststore.password`
| Password of the truststore.
| No
| `${BACKEND_TRUSTSTORE_PASSWORD}`

| `connector.link.backend[n].link-config.properties.endpoint.truststore.type`
| Truststore format: `JKS` or `PKCS12`.
| Yes
| By default, `JKS`

| `connector.link.backend[n].link-config.properties.endpoint.encrypt-alias`
| Default truststore alias used to encrypt outgoing messages when a partner does not define `encryption-alias`.
| No
| `<backend-cert-alias>`

| `connector.link.backend[n].link-config.properties.logging-enabled`
| Logs the full SOAP traffic of this link, including business payloads. The template enables it; disable it in production.
| Yes
| By default, `false`

| `connector.link.backend[n].link-config.properties.ws-policy`
| WS-SecurityPolicy applied to the endpoint. Change it only if agreed with all backend applications.
| Yes
| By default, `classpath:/policy/backend.policy.xml`

| `connector.link.backend[n].link-config.properties.publish-address`
| Path, relative to `cxf.path` (`/services`), of the SOAP endpoint called by the backends. *Keep `/backend`*: only `/services/backend` is excluded from JWT authentication in this version; other values are rejected with HTTP 401.
| Yes
| By default, `/backend`
|===

.Link partner properties
[cols="35,40,10,15", options="header"]
|===
| Property | Description | Optional | Example

| `connector.link.backend[n].link-partners[m].name`
| Unique name of the backend application. Referenced by the routing rules and stored with each message as its backend name. Choose a stable name: changing it later breaks the association of existing conversations.
| No
| `<backend-courts>`

| `connector.link.backend[n].link-partners[m].description`
| Free-text description.
| Yes
| `<Case management system of ...>`

| `connector.link.backend[n].link-partners[m].enabled`
| Whether the partner may exchange messages.
| No
| `true`

| `connector.link.backend[n].link-partners[m].sender-mode`
| How inbound messages are delivered to this partner (see <<backend-delivery-modes>>): `push`, or `pull` / `passive`.
| No
| `push`

| `connector.link.backend[n].link-partners[m].properties.certificate-dn`
| Subject DN of the certificate the backend uses to sign its SOAP requests. See <<certificate-dn-format>>.
| No
| `cn=backend-courts,o=ministry of justice,c=xx`

| `connector.link.backend[n].link-partners[m].properties.encryption-alias`
| Alias of the partner's certificate in the link truststore, used to encrypt messages sent to this partner.
| Yes
| `<backend-courts-cert>`

| `connector.link.backend[n].link-partners[m].properties.push-address`
| URL of the partner's `DomibusConnectorBackendDeliveryWebService` endpoint, provided by the backend team. Required for `push`, ignored otherwise.
| Required for `push`
| `https://<backend-host>/services/domibusConnectorDeliveryWebservice`
|===

[[certificate-dn-format]]
=== Format of `certificate-dn`

The Connector lower-cases the DN of the calling certificate and compares it *character by character* with the configured value. Therefore:

* write the complete subject DN, *entirely in lower case*;
* use the RFC 2253 form produced by Java, with attributes in the same order as in the certificate and no space after the commas, for example `cn=backend-courts,o=ministry of justice,c=xx`;
* the template comment "lower- or UPPERcase is ignored" is wrong: a value containing upper-case letters never matches.

TIP: Print the subject of the backend certificate with `keytool -printcert -file <backend>.cer` (or `openssl x509 -noout -subject -nameopt RFC2253 -in <backend>.pem`) and lower-case it.
With `DEBUG` logging enabled for `eu.ecodex.connector`, the Connector logs the DN it received (`retrieving backend client: ...`).

[[backend-delivery-modes]]
=== Delivery modes

The backend always *submits* messages to the Connector with the `submitMessage` operation of `DomibusConnectorBackendWebService`.
For messages received from the gateway, two delivery modes exist:

[cols="1,4", options="header"]
|===
| `sender-mode` | Behaviour

| `push`
| The Connector calls the backend's `DomibusConnectorBackendDeliveryWebService` (`deliverMessage`) at `push-address`. The backend must expose that web service.

| `pull` or `passive`
| The Connector keeps the message in status *ready for download*. The backend retrieves it with `DomibusConnectorBackendWebService`:

. `listPendingMessageIds` – lists the transport identifiers of the messages waiting for this backend;
. `getMessageById` – downloads one message;
. `acknowledgeMessage` – confirms (or reports the failure of) the processing of that message.

`requestMessages` (download of all pending messages in one call, without acknowledgement) is also available for backends written for older connector versions. The acknowledged mechanism is recommended.
|===

A backend can only list, download and acknowledge its own messages.

== Example

The following example declares two backend applications on one link, one in push mode and one in pull mode.
All values in angle brackets must be replaced.

.Configuration Example
[source,properties]
----
connector.link.backend[0].link-config.name=<national-backends>
connector.link.backend[0].link-config.properties.publish-address=/backend
connector.link.backend[0].link-config.properties.logging-enabled=false

connector.link.backend[0].link-config.properties.endpoint.keystore.path=file:./config/keystores/<backend-keystore>.p12
connector.link.backend[0].link-config.properties.endpoint.keystore.type=PKCS12
connector.link.backend[0].link-config.properties.endpoint.keystore.password=${BACKEND_KEYSTORE_PASSWORD}
connector.link.backend[0].link-config.properties.endpoint.private-key.alias=<connector-backend-key>
connector.link.backend[0].link-config.properties.endpoint.private-key.password=${BACKEND_KEY_PASSWORD}
connector.link.backend[0].link-config.properties.endpoint.truststore.path=file:./config/keystores/<backend-truststore>.p12
connector.link.backend[0].link-config.properties.endpoint.truststore.type=PKCS12
connector.link.backend[0].link-config.properties.endpoint.truststore.password=${BACKEND_TRUSTSTORE_PASSWORD}
connector.link.backend[0].link-config.properties.endpoint.encrypt-alias=<backend-courts-cert>

# backend application delivered by push
connector.link.backend[0].link-partners[0].name=<backend-courts>
connector.link.backend[0].link-partners[0].enabled=true
connector.link.backend[0].link-partners[0].sender-mode=push
connector.link.backend[0].link-partners[0].properties.certificate-dn=<cn=backend-courts,o=...,c=xx  (lower case)>
connector.link.backend[0].link-partners[0].properties.encryption-alias=<backend-courts-cert>
connector.link.backend[0].link-partners[0].properties.push-address=https://<courts-host>/services/domibusConnectorDeliveryWebservice

# backend application pulling its messages
connector.link.backend[0].link-partners[1].name=<backend-registry>
connector.link.backend[0].link-partners[1].enabled=true
connector.link.backend[0].link-partners[1].sender-mode=pull
connector.link.backend[0].link-partners[1].properties.certificate-dn=<cn=backend-registry,o=...,c=xx  (lower case)>
connector.link.backend[0].link-partners[1].properties.encryption-alias=<backend-registry-cert>
----

WARNING: The REST backend API does not identify the caller yet and always uses the partner whose `certificate-dn` is `cn=alice` (see the security guidance of the installation guide). Use the SOAP backend API for production backends.
