= Message Processing Configuration

This configuration defines message processing behavior for the connector platform, including:

* Evidence forwarding
* Automatic delivery evidence
* ebMS identifier generation
* Message identifier suffix configuration
* Transport identifier configuration
* Verification modes for inbound and outbound messages

These settings influence how messages are created, validated, tracked, and exchanged between gateway and backend systems.

== Basic configuration
Configuration is provided via `application.properties` under the `+connector.message-processing.*+` prefix.

.Message Processing Configuration Properties
[cols="35,40,10,15", options="header"]
|===
| Property | Description | Optional | Example

| `connector.message-processing.send-generated-evidences-to-backend`
| Whether REM evidence generated by the connector (e.g., submission acceptance/rejection, delivery/non-delivery evidence) is forwarded to the backend application, or only kept/sent on the gateway side.
| Yes
| `true/false`. By default, set to *true*

| `connector.message-processing.auto-trigger-delivery-evidences`
| Whether the connector automatically generates a `DELIVERY` evidence once an inbound message has been delivered to (pushed to, or downloaded by) the backend. When disabled, the backend must trigger the delivery evidence itself.
| Yes
| `true/false`. By default, set to *false* when the property is absent; the sample configuration sets *true*.

| `connector.message-processing.ebms-id-generator-enabled`
| Whether the connector auto-generates ebMS message IDs itself rather than relying on IDs supplied by the backend.
| Yes
| `true/false`. By default, set to *true*

| `connector.message-processing.ebms-id-suffix`
| Domain suffix appended when generating ebMS message IDs (formatted as `<uuid>@<suffix>`, similar to an e-mail Message-ID). Only takes effect when the generator above is enabled.
| Yes
| `connector.ecodex.eu`

| `connector.message-processing.identifier-suffix`
| Domain suffix used when generating connector message identifiers.
| Yes
| `connector.ecodex.eu`

| `connector.message-processing.transport-id-suffix`
| Domain suffix used for transport step identifiers.
| Yes
| `connector.ecodex.eu`

| `connector.message-processing.outbound-message-verification-mode`
| How strictly outbound messages (backend → gateway) are verified against the processing mode before being sent.
| Yes
| `STRICT/RELAXED`. By default, set to *STRICT*.

| `connector.message-processing.inbound-message-verification-mode`
| How strictly inbound messages (gateway → backend) are verified against the processing mode upon receipt.
| Yes
| `STRICT/RELAXED`. By default, set to *RELAXED*.

|===

For verification mode:

* *STRICT* — the service and action of the message must be declared in the processing mode of the business domain.
* *RELAXED* — same checks as *STRICT*, plus the `fromParty` and `toParty` (identifier and role) must be declared in the processing mode. An empty party identifier type is accepted with a warning.
* *CREATE* — accepted by the configuration but not supported: every message is rejected.

NOTE: In the current implementation *RELAXED* performs more checks than *STRICT* (party verification). This is expected to be revisited; check the release notes before relying on it.

WARNING: Earlier versions of this guide and of the sample configuration used `outbound-verification-mode` and `inbound-verification-mode`.
These names are not bound by the connector and are silently ignored; use the names above.

The three suffix properties default to `connector.ecodex.eu`. Set them to a domain you control so that generated identifiers can be traced to your deployment.

.Configuration Example
[source,properties]
----
connector.message-processing.send-generated-evidences-to-backend=true
connector.message-processing.auto-trigger-delivery-evidences=true
connector.message-processing.ebms-id-generator-enabled=true
connector.message-processing.ebms-id-suffix=connector.ecodex.eu
connector.message-processing.identifier-suffix=connector.ecodex.eu
connector.message-processing.transport-id-suffix=connector.ecodex.eu
connector.message-processing.outbound-message-verification-mode=STRICT
connector.message-processing.inbound-message-verification-mode=RELAXED
----
