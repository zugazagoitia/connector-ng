[[platform-configuration]]
= Platform Configuration

This chapter covers the Spring Boot and infrastructure settings of the **Connector**: HTTP server, database, JMS broker, transactions, uploads, CORS, API documentation, monitoring and logging.
All settings are provided in `config/application.properties`.

[[environment-variables]]
== Environment variables used by the sample configuration

The sample `application.properties` reads the following environment variables.
Every one of them must be defined (or the placeholder replaced by a literal value), otherwise the application fails to start with `Could not resolve placeholder`.

[cols="2,3,3", options="header"]
|===
| Variable | Property | Example

| `DB_URL` | `spring.datasource.url` | `jdbc:mysql://db-host:3306/connector`
| `DB_USERNAME` | `spring.datasource.username` | `connector`
| `DB_PASSWORD` | `spring.datasource.password` | _(secret)_
| `DB_DRIVER_CLASSNAME` | `spring.datasource.driver-class-name` | see <<platform-database>>
| `DB_DIALECT` | `spring.jpa.database-platform` | see <<platform-database>>
| `BROKER_URL` | `spring.activemq.broker-url` | `tcp://activemq-host:61616`
| `BROKER_USER` | `spring.activemq.user` | `connector`
| `BROKER_PASSWORD` | `spring.activemq.password` | _(secret)_
| `S3_ACCESS_KEY` | `connector.file.storage.s3.access-key` | _(secret)_
| `S3_SECRET_KEY` | `connector.file.storage.s3.secret-key` | _(secret)_
| `S3_REGION` | `connector.file.storage.s3.region` | `eu-west-1`
| `S3_BUCKET` | `connector.file.storage.s3.bucket` | `attachments`
| `S3_ENDPOINT` | `connector.file.storage.s3.endpoint` | `https://s3.eu-west-1.amazonaws.com`
| `TEMP_DIR_LOCATION` | `spring.servlet.multipart.location` | `/app/temp`
| `JWT_SECRET_KEY` | `connector.auth.security.jwt.secret` | output of `openssl rand -base64 32`
|===

TIP: Any other property can also be supplied as an environment variable using Spring Boot's relaxed binding, e.g. `CONNECTOR_ADMIN_PASSWORD` for `connector.admin.password`.

== HTTP server

[cols="35,40,10,15", options="header"]
|===
| Property | Description | Optional | Example

| `server.port`
| HTTP port of the REST API, SOAP API, Swagger UI and Actuator.
| Yes
| `30000`

| `server.address`
| Network interface to bind to.
| Yes
| `0.0.0.0`

| `cxf.path`
| Base path of the SOAP endpoints. The backend SOAP endpoint is published at `{cxf.path}{publish-address}`, i.e. `/services/backend` by default.

[[platform-database]]
== Database

[cols="35,40,10,15", options="header"]
|===
| Property | Description | Optional | Example

| `spring.datasource.url`
| JDBC URL of the connector schema.
| No
| `jdbc:mysql://db-host:3306/connector`

| `spring.datasource.username` / `spring.datasource.password`
| Database credentials.
| No
| _(secret)_

| `spring.datasource.driver-class-name`
| JDBC driver or XA data source class (see the table below).
| No
| `com.mysql.cj.jdbc.MysqlXADataSource`

| `spring.jpa.database-platform`
| Hibernate dialect.
| No
| `org.hibernate.dialect.MySQLDialect`

| `spring.jpa.hibernate.ddl-auto`
| Schema management. The sample configuration uses `update`, which is suitable for development only. Use `validate` or `none` in production together with the provided database scripts.
| Yes
| `none`
|===

.JDBC driver, XA data source and dialect per database
[cols="1,2,2,2", options="header"]
|===
| Database | JDBC driver class | XA data source class | Dialect

| MySQL | `com.mysql.cj.jdbc.Driver` | `com.mysql.cj.jdbc.MysqlXADataSource` | `org.hibernate.dialect.MySQLDialect`
| MariaDB | `org.mariadb.jdbc.Driver` | `org.mariadb.jdbc.MariaDbDataSource` | `org.hibernate.dialect.MariaDBDialect`
| PostgreSQL | `org.postgresql.Driver` | `org.postgresql.xa.PGXADataSource` | `org.hibernate.dialect.PostgreSQLDialect`
| Oracle | `oracle.jdbc.OracleDriver` | `oracle.jdbc.xa.client.OracleXADataSource` | `org.hibernate.dialect.OracleDialect`
|===

NOTE: The data source is enlisted in XA transactions by the JTA transaction manager (Atomikos).
The sample environment files set `DB_DRIVER_CLASSNAME` to the XA data source class for MySQL (`com.mysql.cj.jdbc.MysqlXADataSource`), while the comments of the sample `application.properties` list the plain JDBC driver classes.
Until this is aligned, use the value from the sample environment file of your release.

== JMS broker (ActiveMQ Classic)

The Connector connects to the shared external ActiveMQ Classic broker with the standard Spring Boot properties.

[cols="35,40,10,15", options="header"]
|===
| Property | Description | Optional | Example

| `spring.activemq.broker-url`
| OpenWire URL of the broker. Use `ssl://` for TLS or `failover:(...)` for a broker network.
| No
| `tcp://activemq-host:61616`

| `spring.activemq.user` / `spring.activemq.password`
| Broker credentials.
| No
| _(secret)_

| `spring.activemq.packages.trust-all`
| Allows deserialization of any class from JMS object messages. The sample configuration sets `true`; prefer `spring.activemq.packages.trusted` with an explicit package list.
| Yes
| `false`

| `spring.jms.listener.min-concurrency` / `spring.jms.listener.max-concurrency`
| Number of concurrent consumers per queue listener.
| Yes
| `1` / `10`
|===

Redelivery of failed messages is fixed in the current version: at most 5 redeliveries, an initial delay of 60 seconds and a back-off multiplier of 2.
The commented `+connector.activemq.address-settings.*+` properties in the sample configuration are not yet configurable.

== Distributed transactions (JTA / Atomikos)

The Connector uses Atomikos to coordinate database and JMS transactions.

[cols="35,40,10,15", options="header"]
|===
| Property | Description | Optional | Example

| `spring.jta.enabled`
| Enables JTA transaction management. Must stay `true` in production.
| Yes
| `true`

| `spring.jta.log-file`
| Location of the transaction log used for crash recovery. Must be on persistent storage.
| Yes
| `./data/jtalog`

| `spring.jta.atomikos.datasource.max-pool-size`
| Maximum size of the XA database connection pool.
| Yes
| `60`

| `spring.jta.atomikos.connectionfactory.max-pool-size`
| Maximum size of the XA JMS connection pool.
| Yes
| `60`

| `spring.jta.atomikos.properties.default-jta-timeout` / `spring.jta.atomikos.properties.max-timeout`
| Default and maximum transaction timeout. Increase them if large attachments are processed.
| Yes
| `3m`
|===

== File uploads

Attachments are uploaded through multipart requests. The sample configuration accepts files up to 200 MB.

[cols="35,40,10,15", options="header"]
|===
| Property | Description | Optional | Example

| `spring.servlet.multipart.max-file-size`
| Maximum size of a single uploaded file.
| Yes
| `200MB`

| `spring.servlet.multipart.max-request-size`
| Maximum size of a multipart request.
| Yes
| `210MB`

| `spring.servlet.multipart.location`
| Temporary directory for uploads. Must exist and be writable.
| Yes
| `${TEMP_DIR_LOCATION}`

| `server.tomcat.max-part-count`
| Maximum number of parts in a multipart request.
| Yes
| `50`
|===

== CORS

Cross-origin requests are needed when the administration portal is served from another origin than the Connector.

[cols="35,40,10,15", options="header"]
|===
| Property | Description | Optional | Default

| `connector.cors.allowed-origins`
| Allowed origins. Set it explicitly: the default allows every origin.
| Yes
| `+*+`

| `connector.cors.allowed-methods`
| Allowed HTTP methods.
| Yes
| `GET, POST, PUT, PATCH, DELETE, OPTIONS`

| `connector.cors.allowed-headers`
| Allowed request headers.
| Yes
| `+*+`

| `connector.cors.allow-credentials`
| Whether credentials are allowed in cross-origin requests.
| Yes
| `true`

| `connector.cors.max-age`
| How long (seconds) the browser caches the pre-flight response.
| Yes
| `3600`
|===

== Monitoring (Actuator and OpenTelemetry)

[cols="35,40,10,15", options="header"]
|===
| Property | Description | Optional | Example

| `management.endpoints.web.exposure.include`
| Actuator endpoints exposed over HTTP. Actuator endpoints do not require authentication.
| Yes
| `health,info`

| `management.endpoint.health.show-details`
| Level of detail of the health endpoint. The sample uses `always`; use `never` or `when-authorized` when the endpoint is reachable from untrusted networks.
| Yes
| `never`

| `management.otlp.metrics.export.enabled`
| Enables export of metrics over OTLP.
| Yes
| `false`

| `management.otlp.export.url`, `management.opentelemetry.tracing.export.otlp.endpoint`, `management.opentelemetry.logging.export.otlp.endpoint`
| OTLP collector endpoints for metrics, traces and logs.
| Yes
| `http://localhost:4318/v1/traces`

| `management.tracing.sampling.probability`
| Fraction of requests that are traced.
| Yes
| `1.0`
|===

NOTE: The Actuator `metrics` endpoint is currently disabled because the Apache CXF metrics integration is not yet compatible with Spring Boot 4 (see `spring.autoconfigure.exclude` in the sample configuration).
