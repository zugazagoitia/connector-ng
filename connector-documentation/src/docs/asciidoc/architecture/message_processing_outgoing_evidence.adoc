= Processing of an outgoing evidence message

This chapter describes how evidence is generated and submitted when triggered from the backend or as a side effect of outbound business message processing.

== Evidence trigger from the backend

The backend can request evidence generation by submitting an evidence trigger message via the backend SOAP API.
The trigger specifies the evidence type (for example `DELIVERY`) and references the original business message via `referenceToIdentifier`.

[plantuml,outgoing_evidence_1,format=png, opts=inline]
----
@startuml

DomibusConnectorBackendWebService --> ConnectorBackendWebServiceController : submitMessage (trigger)
ConnectorBackendWebServiceController --> ConnectorJmsOutboundEvidenceTriggerPublisher
ConnectorJmsOutboundEvidenceTriggerPublisher --> outboundEvidenceTriggerQueue

@enduml
----

The message is transformed from the SOAP transition model to the internal `ConnectorMessage` domain model and staged for asynchronous processing.

== Evidence trigger processing

`ConnectorJmsOutboundEvidenceTriggerListener` consumes trigger messages from the outbound evidence trigger queue and delegates to `ConnectorOutboundEvidenceMessageProcessorService` (the 7.x counterpart of `EvidenceMessageProcessor` and `EvidenceTriggerStep` in connector 6.x).

[plantuml,outgoing_evidence_2,format=png, opts=inline]
----
@startuml

top to bottom direction
skinparam monochrome false
skinparam linetype ortho

queue outboundEvidenceTriggerQueue

package connector-infrastructure {
  component ConnectorJmsOutboundEvidenceTriggerListener
}

package connector-application {
  component ConnectorOutboundEvidenceMessageProcessorService
  component ConnectorMessageEvidenceCreator
  component ConnectorEvidenceMessageCreator
  component ConnectorMessageEvidenceVerifier
  component ConnectorLinkSubmitter
}

outboundEvidenceTriggerQueue --> ConnectorJmsOutboundEvidenceTriggerListener
ConnectorJmsOutboundEvidenceTriggerListener --> ConnectorOutboundEvidenceMessageProcessorService
ConnectorOutboundEvidenceMessageProcessorService --> ConnectorMessageEvidenceCreator : build REM evidence XML
ConnectorOutboundEvidenceMessageProcessorService --> ConnectorMessageEvidenceVerifier : validate against business message
ConnectorOutboundEvidenceMessageProcessorService --> ConnectorEvidenceMessageCreator : wrap as confirmation message
ConnectorOutboundEvidenceMessageProcessorService --> ConnectorLinkSubmitter : submit to gateway
ConnectorOutboundEvidenceMessageProcessorService --> ConnectorLinkSubmitter : optionally submit to backend

@enduml
----

Processing steps:

. Validate that the message is an evidence trigger and triggering is allowed.
. Resolve the referenced gateway-to-backend business message via `referenceToIdentifier`.
. Build the ETSI-REM evidence XML of the requested type using `ConnectorMessageEvidenceCreator` and `ConnectorEvidenceToolkitImpl`.
. Verify evidence applicability against previously received evidence.
. Create a confirmation message and submit it to the gateway via `ConnectorLinkSubmitter`.
. When `connector.message-processing.send-generated-evidences-to-backend` is enabled, also forward the evidence to the backend.

== Evidences generated during outbound business processing

When an outbound business message is processed by `ConnectorOutboundMessagePipeline`, evidences are generated automatically:

* `ConnectorOutboundMessageAcceptanceStep` creates `SUBMISSION_ACCEPTANCE` after successful gateway validation.
* On submission failure, `ConnectorOutboundMessageRejectionStep` creates `SUBMISSION_REJECTION`.

The confirmation message is submitted back to the backend via `ConnectorLinkSubmitter`.

== Message submitted to the gateway

Evidence confirmation messages destined for the gateway are submitted through the gateway link client.

[plantuml,outgoing_evidence_3,format=png, opts=inline]
----
@startuml

top to bottom direction
skinparam monochrome false
skinparam linetype ortho

package connector-application {
  component ConnectorLinkSubmitter
}

package connector-infrastructure {
  component ConnectorJmsGatewayLinkPublisher

queue gatewaySubmissionQueue

ConnectorLinkSubmitter --> ConnectorJmsGatewayLinkPublisher
ConnectorJmsGatewayLinkPublisher --> gatewaySubmissionQueue : submitMessage

@enduml
----

Before submission, the internal domain message is transformed back to the SOAP transition model of the API.
